    실제 앱 흐름 (제안)

    API 초안 3.3의 I-1(식별)과 I-2(수집 저장)에 맞춘 흐름이에요. 종은 사용자가 확정하고, 엘프는 확정한 종의 속 → 과로 정해요.

    1. 1촬영가이드: "잎이나 꽃을 화면 가득". 긴 변 1280px JPEG로 줄여 업로드
    2. 2식별 (I-1)Pl@ntNet 후보 → DB에서 species_id·엘프(속 → 과) 채움. 한국 이름은 DB에 있으면 바로, 없으면 비워 두고 바로 응답
    3. 3속 신뢰도로 화면 분기아래 3단계. 엘프와 "새 엘프!" 표시도 여기서
    4. 4종 확정1순위를 미리 고른 후보 카드 3개 + "목록에 없어요"(이름 검색 · 다시 찍기). 번역 중인 이름은 실시간으로 채워짐
    5. 5수집 저장 (I-2)save_discovery → 도감 등록, 엘프 획득 연출. species_id로 저장해서 번역이 안 끝나도 저장 가능

    에러: NO_PLANT_FOUND → 다시 찍기 안내, DAILY_LIMIT → 내일 다시, IDENTIFY_FAILED → 잠시 후 다시 (사진은 그대로 두고 재시도 버튼).

    한국 이름(한글화)은 언제 채우나 (제안)

    Pl@ntNet은 한국어 이름을 주지 않아요. 후보를 고르는 화면에서 한국 이름이 필요하니, 고른 뒤가 아니라 식별(I-1) 직후 백그라운드에서 시작해요.

    1. I-1에서 DB를 먼저 봐요. DB에 있는 종은 korean_name을 바로 채워요. 흔한 종을 미리 넣어 두면 대부분 여기서 끝나요.
    2. DB에 없는 종은 종 줄만 먼저 만들고 바로 응답해요. species_id는 주고 korean_name은 비워 둬요. 번역을 기다리지 않으니 응답은 Pl@ntNet 속도(중앙값 ) 그대로예요.
    3. 백그라운드에서 번역해요. 이름이 빈 후보(최대 3개)를 동시에 표준 목록 → 사전 → LLM 순서로 채우고 korean_name_source에 출처를 남겨요 (초안 그대로).
    4. 후보 화면은 임시 이름 → 실시간 교체. 번역 중에는 "밤나무속 식물"처럼 속 이름을 보여주고, Supabase Realtime으로 해당 종 줄을 구독하다가 이름이 들어오면 카드를 바꿔요.
    5. 저장은 기다리지 않아요. I-2는 species_id로 저장하니 번역 전에 골라도 돼요. 도감도 같은 방식으로 나중에 채워져요.

    API 초안에 추가할 것: 후보에 korean_name_status: "ready" | "pending" | "failed". null만으로는 "번역 중"과 "번역 실패"를 구분할 수 없어요.

    번역이 자주 일어날 곳: 이번 테스트에서 틀린 종 대부분이 Castanea sativa, Taxus canadensis처럼 같은 속의 외국 종이었어요. DB에 없을 가능성이 높아요. 아래 "한국 종으로 바꿔 주기"를 같이 하면 번역할 일 자체가 줄어요.

    검수: LLM이 만든 이름은 korean_name_source: llm으로 표시해 두고 나중에 검수해요 (초안 그대로).

    엘프를 속·과 중 어디까지 정하나 (제안)

    후보들의 점수를 속별·과별로 더해서 정해요. 엘프 규칙(속 → 과)과 같은 순서예요. 테스트 화면 결과 카드에도 이 판정이 나와요.

    1. 속으로 정해요 — 1위 속 점수가 2위 속의 2배 이상일 때 (점수가 낮아도 다른 속과 차이가 크면 OK)
    2. 과로 정해요 — 속은 비슷하게 갈리는데 한 과가 전체의 80% 이상일 때 (예: 밀·호밀 → 벼과)
    3. 판정 보류, 한 장 더 — 속도 과도 흩어질 때

    종 후보는 어떻게 보여주나 (제안)

    기준은 속 신뢰도예요. 후보 3개 중 1순위와 같은 속인 후보의 점수를 더한 값이고, 테스트 화면의 "엘프 판별 · 속" 숫자와 같아요.

    정확도를 높이는 방법

    효과가 크고 바로 할 수 있는 것부터 적었어요. "검증 필요"는 아직 테스트하지 않은 방법이에요.

    1. 종 확정은 사용자에게 맡기기바로 적용

      1순위 종 정답은 이지만 후보 3개 안에는 이 들어 있었어요. 후보 카드에서 한 번 고르게 하면 도감에 잘못 들어가는 종이 크게 줄어요.

    2. 한국 종으로 바꿔 주기 (DB 매칭)바로 적용

      밤나무 → Castanea sativa(유럽밤나무), 주목 → Taxus canadensis, 소나무 → Pinus pinea처럼 속은 맞고 종만 외국 종으로 나오는 경우가 있었어요. 후보 학명이 DB에 없으면 같은 속의 한국 종(예: Castanea crenata)을 후보로 보여주면 돼요. 이 경우 엘프는 이미 맞으니 엘프 판별에는 영향이 없어요. 외국 종 이름을 번역할 일도 줄어요.

    3. 촬영 가이드바로 적용

      나무 전체를 찍은 사진은 종 정답이 낮았어요 (). 촬영 화면에 "잎이나 꽃을 화면 가득, 한 그루만" 안내와 예시 사진을 넣어요.

    4. 애매하면 한 장 더 찍기검증 필요

      Pl@ntNet은 같은 식물 사진을 한 번에 여러 장(최대 5장) 받아서 함께 판단해요. 속 신뢰도가 낮을 때 "잎 한 장, 꽃 한 장 더"를 받아 다시 보내면 나아질 가능성이 커요. 사진을 여러 장 보내도 요청은 1회로 세요.

    5. 후보를 10개 받아서 거르기테스트함 · 적용

      후보를 10개 받아 보니 4~10위에서 정답 종이 더 나왔어요. 안암 주목은 1위가 Taxus canadensis였지만 5위에 한국 주목(Taxus cuspidata)이 있었어요. DB에 있는 종·한국에 사는 종을 앞으로 올리면 이런 경우를 잡을 수 있어요. 화면에는 거른 뒤 3개만 보여줘요. 요청 한도는 그대로고 응답은 조금 느려져요 (아래 "후보 3개 vs 10개").

    6. 지역 식물 목록(project)으로 좁히기검증 필요

      Pl@ntNet은 전 세계 목록(all) 대신 특정 지역·주제 목록으로 식별하는 옵션이 있어요. 한국·동아시아에 맞는 목록이 있는지 확인하고 비교해 볼 만해요.

    7. 사용자 선택을 기록해 두기장기

      사용자가 1순위가 아닌 후보나 "목록에 없어요"를 고른 기록을 모으면, 자주 틀리는 종을 찾아 DB 매칭 규칙을 보강할 수 있어요.

    효과 없음: 사진 부위(organ) 지정. 지정해도 결과가 같아서 앱에는 넣지 않아요 (아래 "핵심 발견" 참고).

    테스트 방법

    목적
    앱의 식별(API 초안 3.3 I-1)에 쓸 Pl@ntNet이 얼마나 맞히는지, 엘프 판별 규칙(속 → 과)에 쓸 만한지 확인해요.
    사진
    세 묶음, 60장이에요. 안암 일대 사진 20장은 iNaturalist에 올라온 안암동·성북천·고려대 인근 관찰 사진이에요. 팀이 실제로 테스트할 동네라 가장 현실에 가까워요. 사용자 관찰 사진 20장은 iNaturalist에 일반 사용자가 폰·카메라로 찍어 올린 사진이에요 (한국에서 흔히 보는 식물). 기준 종은 커뮤니티에서 확인한 관찰 기록을 따랐어요. 위키 대표 사진 20장은 위키백과 문서의 대표 사진이에요 (길거리·공원 식물 14종, 실내 식물 6종). 모두 앱 규칙대로 긴 변 1280px JPEG로 줄여서 보냈어요.
    방법
    사진마다 부위 자동(auto)으로 1번 보냈어요. 위키 사진 중 잎·꽃 사진 15장은 부위를 직접 지정해서 1번 더 보내 비교했어요. 후보는 3개까지 받았어요.
    판정
    1순위 후보의 학명·속·과를 정답과 비교했어요. 학명이 바뀐 식물은 예전 이름도 정답으로 쳤어요 (예: 산세베리아 = Sansevieria trifasciata).

    후보 3개 vs 10개

    같은 사진 60장을 후보 3개(nb-results=3)와 10개로 번갈아 보내 비교했어요 (120회). 먼저 보내는 쪽을 사진마다 바꿔서 순서 영향을 줄였어요.

      핵심 발견

        판정 단계별 정답률

        자동(auto) 기준, 사진 묶음별 20장씩이에요. 엘프는 속으로 정해요. 막대에 올리거나 누르면 틀린 사진이 보여요.

        1순위 신뢰도와 정답 여부

        점 하나가 사진 한 장이에요. 세모는 안암 일대 사진, 동그라미는 사용자 관찰 사진, 네모는 위키 대표 사진이에요. 점에 올리거나 누르면 이름이 보여요. 세로선은 신뢰도 50%예요.

        사진별 결과

        직접 테스트하기 →

        "이 사진으로 테스트"를 누르면 테스트 화면에서 같은 사진을 바로 다시 식별해요. 브라우저가 사진을 한 번 더 압축해서 보내기 때문에 점수가 몇 %p 다를 수 있어요.

          한계와 다음 단계

          • 안암·사용자 사진도 iNaturalist에서 종이 확인된 기록이라 비교적 잘 찍힌 편이에요. 이런 공개 관찰 기록은 Pl@ntNet 학습 데이터에 들어 있었을 수도 있어요. 팀원이 직접 찍은 사진은 정확도가 더 낮을 수 있어요.
          • 안암 사진에는 고려대 자연계캠퍼스에서 찍은 밀·호밀·야생염소풀 같은 재배·시험 작물이 섞여 있어요. 속이 틀린 2장(밀·호밀)이 여기서 나왔어요. 길에서 흔히 보는 식물만 보면 정확도가 더 높을 수 있어요.
          • 안암 사진 20장 중 11장은 커뮤니티 동정이 아니라 촬영자가 붙인 종 이름을 정답으로 썼어요. 정답 자체가 틀렸을 수도 있어요 (사진 카드의 "정답 기준" 참고).
          • 묶음마다 20장은 작은 표본이에요. 1~2장 차이는 우연일 수 있으니 경향을 보는 용도로만 써 주세요.
          • 스킨답서스(Epipremnum aureum)와 E. pinnatum은 분류 기준에 따라 같은 종으로 보기도 해서 판정이 애매해요.
          • 다음 단계: 각자 주변 식물을 폰으로 찍어 테스트 화면에 여러 장 한 번에 넣어 보세요 (태스크 "주변 식물 20장 정확도 테스트").
